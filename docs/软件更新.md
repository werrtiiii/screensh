# 软件更新

自动更新默认开启：启动后检查新版本并后台下载，下次启动时先校验并安装本地已下载的更新。关闭自动更新后仍可手动检查、下载和立即安装。

## 差分下载

Windows NSIS 更新使用 electron-updater 的差分下载：复用本机缓存的旧安装包，通过 HTTP Range 请求下载变化的数据块，再在本地重建完整的新安装包。重建结果需通过完整性校验，安装和启动校验仍沿用现有流程。

下载进度显示本次安装包数据的已下载量与总下载量。当所需下载量小于完整安装包大小时，显示「差分下载」。差分下载完成后，本地仍会存在完整安装包，其文件大小不代表实际网络下载量。

差分依赖旧安装包缓存、版本对应的 `.blockmap` 文件及服务器的分段下载能力。首次安装、缓存被删除、旧版本文件已下架、分段请求或差分校验失败时，更新器自动回退到完整下载，以保证更新可以继续。不能保证所有版本都只需下载固定大小的补丁。

发布时需继续提供完整安装包、`.blockmap` 和 `latest.yml`。旧发行版被清理后，旧客户端若没有对应的本地 blockmap 缓存，可能需要完整更新一次。

## OpenList 优先下载

`app/update-config.json` 中配置了 `mirrorUrl` 和 `openList`：当前更新目录为 `/中国移动云盘/分享/ScreenSh-updates`，游客接口中的相对路径为 `/ScreenSh-updates`。

版本号、安装包大小及 SHA-512 校验值仍从 GitHub 正式发行版读取；安装包和新旧 blockmap 优先从 OpenList 获取，文件缺失、网络或校验失败时回退到同一版本的 GitHub 下载地址。镜像尚未同步时不会让客户端停留在旧版本。

OpenList 仍保留直链签名保护。客户端通过无需登录的游客文件接口，为更新目录中的安装包和差分文件获取当次下载签名，不保存管理员账号、密码或永久访问令牌，也不修改其他目录权限。

发布工作流在 GitHub Release 成功后自动运行 `app/scripts/sync-openlist.cjs`，先上传较小的 `.blockmap` 确认写入通道，再上传这次构建的正式安装包，最后上传 `latest.yml`。上传前校验安装包大小和 SHA-512，上传后刷新列表检查文件大小。保留历史 blockmap，不清理旧文件。同步失败会让工作流明确报错；已经发布的 GitHub Release 仍可正常下载。不要用本地重新打包的同版本安装包替换正式包。

小文件使用 OpenList 表单接口，大于 1 MB 的安装包使用原生 HTTPS 二进制文件流，避免表单缓存整个文件后才尝试秒传。显式覆盖同名文件，携带本地计算的 MD5/SHA-1/SHA-256，供支持的网盘尝试秒传；这些值不代替客户端的 GitHub SHA-512 校验。服务器提前确认成功时关闭剩余文件流。每发送约 1 MB 输出一次不含凭据的进度。连接空闲超过 60 秒中止，单文件总时限为 90 分钟，工作流总时限为 120 分钟，以适应实测较慢的 Actions 到 OpenList 传输。镜像尚未同步完成时，客户端仍可以从 GitHub 下载。

## 远程下载源配置

仓库 main 分支根目录的 `update-sources.json` 是远程配置。客户端每次检查更新时读取它（最多等待 5 秒、最多 16 KB），仅接受 HTTPS 下载目录。读取失败或配置无效时保留当前进程中上次有效的地址，首次读取失败时使用随客户端打包的地址。远程配置不允许更换 GitHub 发行仓库、版本或校验值。

以后更换域名或目录，只需修改并提交这个文件：

- `mirrorUrl`：包含 `/d/` 和完整存储路径的下载目录，以 `/` 结尾。
- `openList.url`：客户端使用的游客 HTTPS 入口，当前统一为 `https://file.rn1.me`。
- `openList.path`：游客账号看到的更新目录相对路径，用于获取下载签名。
- `publish.path`：专用上传账号看到的目标目录；账号根目录已经限定为更新文件夹，因此当前为 `/`。
- `publish.url`：仅供 GitHub Actions 上传登录的 HTTPS 接口地址，当前为 `https://file.4.rn1.me:16667`。客户端不读取这个字段。显式区分上传接口，避免向会跳转的游客入口提交上传密码。

当前实测 `file.rn1.me` 的游客接口及下载入口会返回 HTTP 307，跳转到 `file.4.rn1.me:16667`；客户端匿名请求可以跟随跳转。若希望游客始终只访问 `file.rn1.me`，需在服务器或域名入口改用反向代理，而不是返回域名跳转。客户端配置本身无法取消服务器的 HTTP 跳转。

发布流程也会从 main 分支读取当前配置，而不是使用版本标签中可能过时的地址。修改 OpenList 目录时，同时调整上传账号的基本路径。更换上传密码时更新 GitHub Secret。只有包含远程配置功能的新客户端能读取此文件；旧客户端仍按原地址下载，失败后回退 GitHub。

## 首次启用自动同步

创建专用账号 `screensh-publisher`，基本路径仅设为 `/中国移动云盘/分享/ScreenSh-updates`，只授予「写入内容（创建/上传/修改）」权限，不授予删除、移动等权限。

在仓库 Settings → Secrets and variables → Actions 中添加两个 Repository secrets：`OPENLIST_USERNAME` 和 `OPENLIST_PASSWORD`。密码仅保存在 GitHub Secrets，客户端、仓库配置和日志中均不保存上传凭据。同步脚本使用专用账号登录取得临时 token，禁止携带凭据跟随 HTTP 跳转；域名改变后请使用最终 HTTPS 站点地址。

可在 Actions 中运行 **Sync existing release to OpenList**，输入已发布标签（如 `1.5.3`），它会下载正式发行版原件并同步，适合首次验证、补传或镜像迁移。两个工作流共用同步锁，避免同时覆盖清单。也可用 `node app/scripts/sync-openlist.cjs update-sources.json app/dist` 手动重试；运行前通过环境变量提供相同的两个凭据，使用正式发布的原始文件及清单。

## 本地验证

`node app/tests/integration/smoke-differential-update.cjs` 使用本地 1.5.2 和 1.5.3 安装包及其 blockmap，通过仅绑定回环地址的 HTTP 服务运行更新器原生差分下载和 SHA-512 校验，不执行安装包。也可以通过两个命令行参数指定其他新旧安装包。

该组安装包实测：完整包 194,156,869 字节，传输 42,005,473 字节，复用 152,151,396 字节，减少约 78.4% 的安装包下载量。实际节省比例随版本差异变化。
