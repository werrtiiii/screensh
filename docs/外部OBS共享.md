# 外部 OBS 共享

在 OBS 配置场景和来源后，ScreenSh 可以通过本机 OBS WebSocket 控制开始、停止推流。OBS 通过 WHIP 推送到软件启动的本地 MediaMTX，观看者沿用现有共享观看链路。

## 使用

1. 安装支持 WHIP 和 WebSocket 5 的 OBS Studio，建议使用当前稳定版。
2. 在 OBS 配置场景、来源、声音，以及输出分辨率、帧率和码率。使用浏览器兼容的 H.264 视频编码。
3. 打开 OBS 的「工具 → WebSocket 服务器设置」，启用服务器和密码认证，记下端口、密码。
4. 在 ScreenSh 加入频道，点击「共享屏幕 → 外部 OBS」，填写本机端口和密码，点击「连接 / 刷新预览」。
5. 确认场景后点击「开始 OBS 共享」。无需手动填写本地推流地址。
6. 点击 ScreenSh 的「停止共享」，或在 OBS 中停止推流。

连接仅访问 `127.0.0.1`；密码在 Windows 本地加密保存，连接后输入框清空。留空保留保存的密码，「清除密码」后重新连接可移除保存的密码。

外部 OBS 模式使用 OBS 的画面、音频和编码设置，ScreenSh 的画质自适应不调整外部 OBS。预览是连接时的场景截图，点击刷新可重新获取。OBS 已在直播时，软件拒绝接管，需先停止现有推流。

## 停止与恢复

软件开始共享前暂存 OBS 原推流服务设置，停止共享后恢复；不会读取或修改场景来源。OBS 手动停止或控制连接中断会结束共享，保留服务器和频道语音连接。

如果 OBS 已退出而无法立即恢复，ScreenSh 在本次运行中保留待恢复设置，之后重新连接同一端口时尝试恢复。若两个程序都异常退出，需在 OBS 中手动检查和恢复推流设置；当前没有跨进程重启的恢复记录。

## 验证范围

自动化测试覆盖 WebSocket 5 密码认证、场景预览、启动中取消、启动失败、重复停止、手动停止、连接断开、原设置恢复，以及真实 MediaMTX 的 WHIP 接收和 Chromium WHEP 视频解码。控制端由协议测试服务模拟，仍需使用安装的 OBS Studio 进行实际双机验证。
