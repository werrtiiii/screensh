# 服务器部署

需要 Linux / NAS、Docker Compose，以及可用的 EasyTier 节点。服务器需能下载 Docker 镜像和 npm 依赖。

## 1. 解压与配置

从 [GitHub Releases](https://github.com/werrtiiii/screensh/releases) 下载服务端压缩包，将完整文件解压到 `/opt/screensh-server`，确保 `compose.yaml` 位于该目录。

编辑 `compose.yaml`，在现有 `environment` 中填写节点，一行一个；其他配置保留：

```yaml
SCREENSH_EASYTIER_PEERS: |-
  tcp://peer.example.com:11010
  udp://other.example.com:11011
```

替换为实际地址，新服务器节点不能为空。默认使用 host 网络和 TCP 31012，确保端口未被占用。

## 2. 启动与连接

```bash
cd /opt/screensh-server
docker compose up -d --build
curl http://127.0.0.1:31012/health
```

健康检查返回 `"status":"ok"`、`"protocol":2` 后，客户端填写 `http://服务器IP:31012` 连接，并开放对应 TCP 端口。首次成功连接的客户端成为房主，可修改服务器设置。

使用域名时，将全部路径反向代理到 `http://127.0.0.1:31012`，启用 HTTPS、WebSocket 和 HTTP Range，客户端填写 `https://你的域名`。`SCREENSH_TRUST_PROXY` 默认是 `loopback`；代理从其他地址连接时，加入实际代理 IP / CIDR，并正确传递 X-Forwarded-For。

## 3. 更新与维护

更新前备份 `screensh-data` 数据卷。覆盖新版文件时保留原 Compose 配置、项目名和数据卷，再执行：

```bash
cd /opt/screensh-server
docker compose up -d --build
```

数据卷挂载到容器 `/app/data`。不要执行 `docker compose down -v`。已有节点需在软件的服务器设置中修改，环境变量不会覆盖保存过的节点。

查看日志：

```bash
docker compose logs --tail=100 screensh-server
```

需要视频转发时，另按[视频转发部署](视频流转发部署.md)配置 MediaMTX。
