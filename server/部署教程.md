# ScreenSh 服务端部署教程

服务端是 Node.js 信令服务，默认监听 TCP 31012，提供 Socket.IO 连接和 `/health` 检查接口。屏幕画面由客户端之间传输。以下步骤适用于 Linux 服务器上的Docker Compose。

## 1. 上传文件

在 1Panel「文件」中新建 `/opt/screensh-server`，上传 `server/` 中的以下九个文件，全部放在同一目录：

```text
Dockerfile
compose.yaml
.dockerignore
package.json
package-lock.json
server.js
easytier-peers.cjs
lolping-protocol.cjs
chat-store.cjs
```

若用 Git 克隆项目，可将上述文件所在的 `server/` 目录作为部署目录。

## 2. 填写组网节点

首次启动前，在 1Panel 文件页面编辑 `/opt/screensh-server/compose.yaml`。将 `SCREENSH_EASYTIER_PEERS: ""` 改成实际可用的 EasyTier 节点地址，一行一个：

```yaml
environment:
  PORT: "31012"
  SCREENSH_STATE_FILE: /app/data/server-state.json
  SCREENSH_EASYTIER_PEERS: |-
    peer.example.com:11010
    udp://other.example.com:11011
```

节点支持 `主机:端口`、`tcp://主机:端口` 和 `udp://主机:端口`，最多 32 个；省略协议时使用 TCP。新服务器未配置节点会拒绝启动，并在容器日志中提示 `SCREENSH_EASYTIER_PEERS`。

## 3. 启动并检查

在「终端」执行：

```bash
cd /opt/screensh-server
docker compose up -d --build
curl http://127.0.0.1:31012/health
```

返回内容应包含 `"status":"ok"` 和 `"protocol":2`。若未启动，执行 `docker compose logs --tail=100 screensh-server` 查看原因。服务器首次构建需要能下载 Node.js Docker 镜像和 npm 依赖。

## 4. 配置域名和客户端

在 1Panel「网站」中创建反向代理，目标地址填写 `http://127.0.0.1:31012`，启用 WebSocket 和 HTTPS。访问 `https://你的域名/health`，确认返回健康状态。若不使用反向代理，需要允许客户端访问服务器的 TCP 31012 端口。

客户端首页可直接填写域名或 IP，例如 `192.168.1.10`，先使用 HTTP/HTTPS 的默认端口，连接失败后再尝试 31012；输入框和书签保留原始填写内容；自定义端口填写 `域名:端口`。使用 HTTPS 反向代理的标准 443 端口时填写 `https://你的域名`，显式填写的协议和端口会保留。旧部署若仍监听 3000，请填写 `域名:3000`，或同步更新 Compose、反向代理和防火墙端口。由准备担任房主的客户端第一个成功进入；只点击「检测」不会占用房主身份。进入后可在「服务器设置」中设置连接密码、修改组网节点。

服务器负责下发组网节点，但节点本身必须对各客户端可达；仅 `/health` 正常不能证明客户端之间的屏幕传输可用。

## 5. 配置保存和更新

服务器状态保存在容器内 `/app/data/server-state.json`，由 Compose 命名卷 `screensh-data` 持久化。房主身份、密码、频道和组网节点都保存在这里。服务器图标和用户头像是独立的图片文件，保存在 `/app/data/media/`，状态文件只记录它们的相对路径。已保存的节点优先于 Compose 环境变量；修改 Compose 不会覆盖已有节点。后续节点变更由房主在客户端「服务器设置 → 组网节点」完成，成员重新连接后使用新节点。

更新服务端时，将新的服务端文件上传到**原部署目录**，保持原来的 `compose.yaml` 节点配置和编排项目名，然后执行：

```bash
cd /opt/screensh-server
docker compose up -d --build
curl http://127.0.0.1:31012/health
```

更新前备份数据卷；不要执行 `docker compose down -v`，也不要删除 `screensh-data`。若从旧编排迁移，先确认它的数据卷名称和挂载位置，避免新编排创建空卷。

## 常见问题

- **临时频道和频道密码**：客户端与服务端需同步更新。所有人可创建临时频道，无人连续五分钟后自动删除；持久频道仅房主、管理员可创建。已有频道保留为持久频道，主频道仍不能删除。服主可管理全部频道密码，其他人只能管理自己创建的频道密码；密码只保存盐和哈希，不向成员广播。主频道设置密码后，未通过验证的用户仍可进入服务器并停留在频道外。

- **报 `Cannot find module './lolping-protocol.cjs'`**：确保已上传同版本的 `lolping-protocol.cjs`、`Dockerfile` 和 `.dockerignore`。Dockerfile 的源码复制行应为 `COPY server.js easytier-peers.cjs lolping-protocol.cjs chat-store.cjs ./`，`.dockerignore` 应包含 `!lolping-protocol.cjs`。然后重新执行 `docker compose up -d --build`；只重启旧容器不会补齐镜像里的文件。

- **容器不断重启**：查看 `docker compose logs --tail=100 screensh-server`；首先确认首次部署已填写节点，且格式正确。
- **31012 端口被占用**：停止旧服务，或修改 `compose.yaml` 中端口映射的左侧端口，并同步修改反向代理目标。
- **域名能打开 `/health`，客户端无法连接**：检查 HTTPS 证书、反向代理的 WebSocket 支持，以及客户端填写的地址是否没有额外路径。
- **能进频道但无法观看**：检查客户端能否连接部署的 EasyTier 节点，以及共享端的网络与媒体端口；信令服务健康不代表媒体链路畅通。
- **房主身份丢失**：房主身份由客户端保存的身份凭据和服务端状态共同决定。更换电脑、清理客户端数据或更换服务器地址后，原身份不会自动恢复。


## 2.4.1 修复与升级

配套客户端 1.4.5。更新时保留原数据卷；旧头像文件及状态文件会自动迁移，房主、管理员和频道继续保留。头像和服务器图标通过鉴权后的信令请求按需获取，状态广播只携带缓存标识，因此两端应一起更新。

### 可信代理与密码限流

新增环境变量 SCREENSH_TRUST_PROXY，默认 loopback，仅信任本机回环地址传入的 X-Forwarded-For。直连公网客户端无法用该请求头伪造限流 IP。

若使用 1Panel / Docker，代理到后端时可能从 Docker 网关或代理容器地址连接。请把实际代理地址加入此项，例如 `loopback,172.18.0.1/32`（这是示例，需替换为你的真实代理地址）。可以填写多个代理 IP / CIDR，用英文逗号分隔；不要信任所有地址或整个公网。

代理应追加或重写 X-Forwarded-For 的真实来源。多级代理需要配置实际可信代理链。服务端使用链中第一个不可信来源作为客户端 IP，不直接相信用户提交的最左侧地址或 CF-Connecting-IP。若部署只允许反向代理访问，建议同时在防火墙中限制后端端口的访问来源。

新部署请继续先填写 SCREENSH_EASYTIER_PEERS，再启动服务端。


## 文字聊天与记录保存

更新文字聊天功能需同步上传 `server.js`、`chat-store.cjs`、`Dockerfile` 和 `.dockerignore` 后重新构建。每个服务器共用一个聊天区，未加入语音频道的服务器成员也可收发消息。

聊天数据位于原数据卷的 `/app/data/chat/`：`chat.json` 保存消息、保留策略和清空版本，`media/` 保存聊天图片（含 GIF/WebP 原始文件）和文件附件，`uploads/` 临时保存分片上传，未完成的上传在取消、断线或超时后清理。备份时包含整个数据卷。服主可在服务器设置中清空聊天记录、设置保存天数和容量上限；默认 30 天、512 MB，超出任意上限会清理最旧消息及不再被引用的图片，0 表示对应项不限。直接预览的聊天图片最大 20 MB；回形针可发送任意类型文件（较大图片以文件形式发送），单条消息含附件不能超过服务器的容量上限，容量设置为 0 时不设此项限制。附件分片上传，下载通过需登录成员授权的短时链接完成；反向代理需将 `/chat-files/` 路径转发到同一个服务端。

客户端默认以 IndexedDB 保存本地聊天记录和已加载图片，默认 30 天、256 MB；系统设置的“聊天”分组支持关闭保存、设置本地保留规则、按服务器或全部清除缓存。清除本地记录不删除服务器数据；服务器清空、自动过期和容量清理不会删除客户端已保存的记录和图片，离线客户端重连后也保留本地历史。本地记录仅由本机保留策略或手动清除管理；尚未下载到本机的图片在服务器删除后无法补充加载。

消息右键可撤回自己两分钟内的消息，服主和管理员可以撤回权限更低成员的消息，不受两分钟限制。撤回与普通历史清理不同：撤回会删除服务器内容和在线客户端对应的本地记录；离线客户端下次同步也会处理撤回。`chat.json` 保留必要的消息身份索引和撤回标记，以便在普通历史清理后仍可同步撤回，不包含已清理的消息正文或附件。已手动下载到系统文件夹的副本不会被远程删除。

MP4 文件在聊天中提供静态封面和点击播放，封面缓存在本机，不自动下载完整视频。播放使用 `/chat-files/` 的成员授权链接与 HTTP Range 分段读取，反向代理请保留 Range/Content-Range 响应。文件下载入口继续保留。视频编码不受当前客户端支持时，可下载后使用本机播放器打开。更新此功能需要同步部署新版服务端。

当前配套版本：客户端 **1.4.15**，频道服务端 **2.5.0**。请完整上传本节所列运行文件；聊天、频道密码及临时频道功能需要新版服务端。
