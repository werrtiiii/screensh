# ScreenSh 服务端部署教程

服务端是 Node.js 信令服务，默认监听 TCP 3000，提供 Socket.IO 连接和 `/health` 检查接口。屏幕画面由客户端之间传输。以下步骤适用于 Linux 服务器上的Docker Compose。

## 1. 上传文件

在 1Panel「文件」中新建 `/opt/screensh-server`，上传 `server/` 中的以下八个文件，全部放在同一目录：

```text
Dockerfile
compose.yaml
.dockerignore
package.json
package-lock.json
server.js
easytier-peers.cjs
lolping-protocol.cjs
```

若用 Git 克隆项目，可将上述文件所在的 `server/` 目录作为部署目录。

## 2. 填写组网节点

首次启动前，在 1Panel 文件页面编辑 `/opt/screensh-server/compose.yaml`。将 `SCREENSH_EASYTIER_PEERS: ""` 改成实际可用的 EasyTier 节点地址，一行一个：

```yaml
environment:
  PORT: "3000"
  SCREENSH_STATE_FILE: /app/data/server-state.json
  SCREENSH_EASYTIER_PEERS: |-
    peer.example.com:11010
    udp://other.example.com:11011
```

节点支持 `主机:端口`、`tcp://主机:端口` 和 `udp://主机:端口`，最多 32 个；省略协议时使用 TCP。新服务器未配置节点会拒绝启动，并在容器日志中提示 `SCREENSH_EASYTIER_PEERS`。

## 3. 启动并检查

在「终端」执行：

```bash
cd /opt/screensh-server
docker compose up -d --build
curl http://127.0.0.1:3000/health
```

返回内容应包含 `"status":"ok"` 和 `"protocol":2`。若未启动，执行 `docker compose logs --tail=100 screensh-server` 查看原因。服务器首次构建需要能下载 Node.js Docker 镜像和 npm 依赖。

## 4. 配置域名和客户端

在 1Panel「网站」中创建反向代理，目标地址填写 `http://127.0.0.1:3000`，启用 WebSocket 和 HTTPS。访问 `https://你的域名/health`，确认返回健康状态。若不使用反向代理，需要允许客户端访问服务器的 TCP 3000 端口。

客户端首页的服务器地址填写 `https://你的域名`。由准备担任房主的客户端第一个成功进入；只点击「检测」不会占用房主身份。进入后可在「服务器设置」中设置连接密码、修改组网节点。

服务器负责下发组网节点，但节点本身必须对各客户端可达；仅 `/health` 正常不能证明客户端之间的屏幕传输可用。

## 5. 配置保存和更新

服务器状态保存在容器内 `/app/data/server-state.json`，由 Compose 命名卷 `screensh-data` 持久化。房主身份、密码、频道和组网节点都保存在这里。服务器图标和用户头像是独立的图片文件，保存在 `/app/data/media/`，状态文件只记录它们的相对路径。已保存的节点优先于 Compose 环境变量；修改 Compose 不会覆盖已有节点。后续节点变更由房主在客户端「服务器设置 → 组网节点」完成，成员重新连接后使用新节点。

更新服务端时，将新的服务端文件上传到**原部署目录**，保持原来的 `compose.yaml` 节点配置和编排项目名，然后执行：

```bash
cd /opt/screensh-server
docker compose up -d --build
curl http://127.0.0.1:3000/health
```

更新前备份数据卷；不要执行 `docker compose down -v`，也不要删除 `screensh-data`。若从旧编排迁移，先确认它的数据卷名称和挂载位置，避免新编排创建空卷。

## 常见问题

- **报 `Cannot find module './lolping-protocol.cjs'`**：确保已上传同版本的 `lolping-protocol.cjs`、`Dockerfile` 和 `.dockerignore`。Dockerfile 的源码复制行应为 `COPY server.js easytier-peers.cjs lolping-protocol.cjs ./`，`.dockerignore` 应包含 `!lolping-protocol.cjs`。然后重新执行 `docker compose up -d --build`；只重启旧容器不会补齐镜像里的文件。

- **容器不断重启**：查看 `docker compose logs --tail=100 screensh-server`；首先确认首次部署已填写节点，且格式正确。
- **3000 端口被占用**：停止旧服务，或修改 `compose.yaml` 中端口映射的左侧端口，并同步修改反向代理目标。
- **域名能打开 `/health`，客户端无法连接**：检查 HTTPS 证书、反向代理的 WebSocket 支持，以及客户端填写的地址是否没有额外路径。
- **能进频道但无法观看**：检查客户端能否连接部署的 EasyTier 节点，以及共享端的网络与媒体端口；信令服务健康不代表媒体链路畅通。
- **房主身份丢失**：房主身份由客户端保存的身份凭据和服务端状态共同决定。更换电脑、清理客户端数据或更换服务器地址后，原身份不会自动恢复。


## 2.4.1 修复与升级

配套客户端 1.4.5。更新时保留原数据卷；旧头像文件及状态文件会自动迁移，房主、管理员和频道继续保留。头像和服务器图标通过鉴权后的信令请求按需获取，状态广播只携带缓存标识，因此两端应一起更新。

### 可信代理与密码限流

新增环境变量 SCREENSH_TRUST_PROXY，默认 loopback，仅信任本机回环地址传入的 X-Forwarded-For。直连公网客户端无法用该请求头伪造限流 IP。

若使用 1Panel / Docker，代理到后端时可能从 Docker 网关或代理容器地址连接。请把实际代理地址加入此项，例如 `loopback,172.18.0.1/32`（这是示例，需替换为你的真实代理地址）。可以填写多个代理 IP / CIDR，用英文逗号分隔；不要信任所有地址或整个公网。

代理应追加或重写 X-Forwarded-For 的真实来源。多级代理需要配置实际可信代理链。服务端使用链中第一个不可信来源作为客户端 IP，不直接相信用户提交的最左侧地址或 CF-Connecting-IP。若部署只允许反向代理访问，建议同时在防火墙中限制后端端口的访问来源。

新部署请继续先填写 SCREENSH_EASYTIER_PEERS，再启动服务端。
