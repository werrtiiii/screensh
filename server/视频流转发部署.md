# 视频转发部署

先完成[服务器部署](部署教程.md)。MediaMTX 需独立运行，以下两种方式选一种。

## 1. 选择配置

### 通过 EasyTier

- 在同一台主机运行 EasyTier 和 MediaMTX，EasyTier 开启 TUN 并取得虚拟 IP。
- 编辑 `mediamtx.external.yml`：将 `10.126.126.1` 全部替换为实际虚拟 IP。
- 在软件的「服务器设置」选择 EasyTier 转发，填写与该节点一致的网络名称、网络密码，以及 MediaMTX 虚拟 IP、HTTP 端口 `8889`。
- 确保虚拟网络内可访问 TCP 8889、UDP/TCP 8189。

### 直连 WHIP / WHEP

- 使用 `mediamtx.direct.yml`，将 `webrtcAdditionalHosts` 中的 `video.example.com` 替换为客户端可达的 IP 或域名。
- 将 `mediamtx.external.compose.yaml` 中挂载的 `mediamtx.external.yml` 改为 `mediamtx.direct.yml`。
- 开放或映射 TCP 18889、UDP/TCP 35686。HTTPS 反向代理仍需单独开放媒体端口，并保留 POST、PATCH、DELETE、Location 和 CORS 响应头。
- 在软件的「服务器设置」选择直连转发，填写根地址，如 `http://服务器IP:18889` 或 `https://video.example.com`，不要附加 `/whip`、`/whep` 或流名称。HTTPS 证书需被客户端信任。

## 2. 配置认证与缓冲

两种模板均需保留 HTTP 认证，将 `authHTTPAddress` 设置为 MediaMTX 可访问的信令服务地址：

```yaml
authMethod: http
authHTTPAddress: http://127.0.0.1:31012/media-relay/auth
authHTTPExclude: []
```

以上适用于同机 host 网络；不同主机需替换为实际可达的地址。使用反向代理时，确认 `/media-relay/auth` 转发到同一信令服务。

模板使用 8 MiB UDP 接收缓冲。Linux 宿主机检查并按需提高上限：

```bash
[ "$(sysctl -n net.core.rmem_max)" -ge 8388608 ] || sudo sysctl -w net.core.rmem_max=8388608
```

需在重启后保留时，将该值写入宿主机的 sysctl 持久配置。

## 3. 启动与启用

在配置文件所在目录执行：

```bash
docker compose -f mediamtx.external.compose.yaml up -d
docker compose -f mediamtx.external.compose.yaml logs --tail=50
```

房主开启「支持外部视频转发」。保存组网名称、密码后，成员退出并重新连接服务器；共享者在共享设置中开启「使用服务器转发」。

修改 MediaMTX 配置后重启：

```bash
docker compose -f mediamtx.external.compose.yaml restart
```

更新镜像时执行 `docker compose -f mediamtx.external.compose.yaml pull`，再执行上述 `up -d`。
